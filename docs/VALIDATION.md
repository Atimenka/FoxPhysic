# Поставка 0.1.0-alpha.5

Дата: 2026-10-11. Цель: Minecraft 1.21.1, Fabric; Windows x64 (MSVC). Подробности: `validation/alpha.5-server-findings.txt`.

## Что добавлено в alpha.5

- Коллизия игрока с телами: игрок стоит на теле, тело не проходит сквозь голову; поправка игрока делается в Java (`Lab.applyContacts`).
- Удар рукой по физическому телу с откидыванием (миксин `ServerPlayNetworkHandlerMixin.onHandSwing`, защита `isOnThread`, одно срабатывание на взмах).
- Гравипушка: захват (ПКМ) и запуск (ЛКМ).
- Предмет assembler и команды `/foxphys assembler give|run`.
- Исправлен разгон тела при перекрытии с игроком: `push = min(depth/dt, 2.0) * 0.1` в `native/src/engine/contacts.rs`; до исправления тело набирало неограниченную скорость (-13 -> -70 м за 5 с).

## Что проверено агентом

- `cargo test --locked`: 77 passed, 0 failed, 1 ignored; `clippy --all-targets -D warnings`: чисто.
- `./gradlew protocolSmoke jniSmoke --rerun` с нативами: `PROTOCOL_SMOKE_OK`, `JNI_SMOKE_OK`. При `-PskipNative` оба смоука SKIPPED, это не проверка.
- Linux release, MSVC release (DLL sha256 `29e4fa79a11cebacf29cde28bf881c1bfebdac29a9bb955b741f30603d133919`), `./gradlew build -PskipNative`.
- На сервере: тело на полу не сдвигается, когда игрок внутри него (игрок выталкивается вбок); `assemble 2` переносит 4 блока, `disassemble 2` возвращает 4 блока; `disassemble` без сборки даёт ошибку.

## Что не подтверждено (ждёт проверки в игре)

- Стояние сверху на теле: агентский бот без физики кикается как «flying». Возможно, артефакт харнесса, но не доказано.
- Захват гравипушкой сверху (взгляд вниз) подтверждён на сервере: «тело #1 захвачено», отпускание работает.
- Захват сбоку из 3.9 блока не сработал (три попытки, «тело не в прицеле»); причина не установлена, это открытый дефект.
- Удар пустой рукой и одиночный взмах с удержанным телом не получены: агентский бот кикается как «flying» на висении.
- Команда `assembler give` (выдача предмета игроку, через RCON не проверяется).
- Тело #1 из предыдущей серии покинуло стенд; причина не установлена.

## Статус пунктов ТЗ

Пункты чек-листа отмечены только там, где есть проверка. Игровые пункты alpha.5 не отмечаются агентом (см. выше). Не начаты: 3D-вода, мягкие тела, NeoForge, Sable, сеть, клиентский рендер, миксины рендера и тиков, NBT-сохранение.

## Ограничения, которые нужно знать

- **Статические блоки и подвижные тела.** Тела сталкиваются с окружением, которое Java сканирует вокруг AABB тела и передаёт в Rust как точные жадные коробки. Скан выполняется каждые 2 тика, поэтому блок, поставленный или сломанный между сканами, на короткое время может быть проигнорирован. Инкрементального обновления коллайдеров нет (`replace_terrain` пересоздаёт всё). Не проверено в игре, что подвижные тела не проходят сквозь блоки в реальной сцене.
- **Отображение.** Block display не дают рендеринга уровня Sable; клиентский рендерер движущихся блоков не сделан. Визуальные объекты обновляются каждый тик, интерполяции нет.
- **Блок-сборщик.** Логика в Rust есть, блок и команды для игрока отсутствуют; правило «перемещать блоки» не реализовано.
- **Sable Companion.** Артефакты существуют (`sable-companion-fabric-1.21.1`, `sable-companion-common-1.21.1`), но интеграция не сделана, API не проверялся.

## Чего НЕ было

- **Minecraft с этим модом не запускался в игровом клиенте.** Игровая проверка не выполнена ни для одной из функций.
- **Windows DLL не загружалась на настоящей Windows.** Она cross-compiled и проверена по структуре (PE, экспорты, импорты).
- Нет измеренного FPS/TPS, длительного теста на сервере, проверки совместимости с другими модами.
- Не сделано: миксины в рендер чанков, клиентский рендерер движущихся блоков, 3D-вода (SPH/PBF/FLIP), двусторонняя связь с водой, сетевая синхронизация, инкрементальные terrain-коллайдеры, нейросетевой слой коллизий (вместо него точное жадное покрытие).

## Первый игровой тест на Windows (обновлён для alpha.2)

## Первый игровой тест на Windows

1. Отдельный Minecraft 1.21.1 Creative мир с Fabric и Fabric API.
2. Windows JAR в `mods`; выполнить `/foxphys demo`.

## alpha.7: видимость физичных блоков (ход 10)

Причина: `PhysicsBlockEntity` не отдавал клиенту NBT с состоянием оригинального блока. В 1.21.1 `getUpdateTag` (Yarn: `toInitialChunkDataNbt`) по умолчанию пуст, клиент получал `originalState = AIR`, и рендерер ничего не рисовал.

Исправление: `PhysicsBlockEntity.toInitialChunkDataNbt` возвращает полный NBT. Проверено по байткоду: переопределение есть в собранном jar.

Не проверено: видимость в игре. Остаётся риск с Sodium: глобальные block entity рисуются только из видимых секций Sodium, и окклюзия может скрыть куб.

Миксин Sodium для физичных блоков (`SodiumPhysicsBlockMixin`): Sodium рисует глобальные block entity только из видимых секций. Миксин дорисовывает живые физичные блоки, чью клетку Sodium не нарисовал. Сигнатуры `renderGlobalBlockEntities` и `isBoxVisible` проверены в Sodium 0.6.13 и 0.8.13. Не проверено в игре.
