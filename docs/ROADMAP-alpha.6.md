# FoxPhys 0.1.0-alpha.6 — план и статус

Дата: 2026-10-11. Статус: **план, код alpha.6 не начат**. Этот документ фиксирует, что уже известно о текущем коде, что ТЗ требует, что проверяемо агентом, а что нельзя отметить без игры.

## 1. Текущее состояние (проверено по коду)

| Тема | Факт |
|---|---|
| Загрузчики | Только Fabric (`build.gradle`, Loom 1.8.13). NeoForge-модуля нет. |
| Модули | Один проект, нет `common/`, `fabric/`, `neoforge/`. |
| Миксины | 3 файла: `ServerPlayNetworkHandlerMixin`, `BlockDisplayAccessor`, `DisplayAccessor`. Миксинов рендера, `ChunkBuilder`, `WorldRenderer`, тиков нет. |
| Лимиты тел | `max_bodies: 64` (`native/src/protocol.rs`). |
| Лимит актёров | `MAX_ACTORS: 64` (`native/src/engine.rs`). |
| Лимит бокса | `MAX_BOX_SIDE: 16` (`assembler.rs`), сборка по боксам, не по «4096 ячеек». Число 4096 из ТЗ в коде не найдено. |
| Вода | `native/src/water.rs`, по памятке 2.5D. Не SPH, не 3D. |
| Плотности | Грубые значения по имени блока в `Lab.java` (например, дерево 550, камень 2600, железо 7800). Датапака нет. |
| Мягкие тела | Нет. |
| Тесты Rust | 78 функций `#[test]`. |
| Игровая проверка | Агентом только на Linux-сервере, с ограничениями харнесса (см. `validation/alpha.5-server-findings.txt`). |

## 2. Что требует ТЗ и оценка

| Задача | Оценка | Заметки |
|---|---|---|
| 1. Игрок на теле (стоять, ехать вместе, crouch) | Выполнимо, высокий приоритет | Сейчас дефект: тело выталкивает игрока. Нужна проверка живым клиентом, харнесс не воспроизводит стояние. |
| 2. Точные меши и хитбоксы по форме | Выполнимо частично | Ступени, плиты, заборы требуют box-разложения по VoxelShape. Hitbox по модели — отдельная работа. |
| 3. Снять лимит, прикрепление блоков | Выполнимо | Лимит 64 тела — параметр; «1000+ блоков» нужно мерить. Chunked assembly — крупная задача. |
| 4. 3D-вода (SPH) | Очень большой объём | SPH в реальном времени на сервере при TPS 20 дорогой. Нужны LOD и бюджет. |
| 4.2 Визуализация воды | Частично | Процедурные волны, Бер–Ламберт, Френель: клиентский код, требует рендера. Шейдерные ссылки (BoralancesShaders, Realis) в ТЗ не проверены. |
| 5. Плотности и датапак | Выполнимо | Таблица из ТЗ: значения по справке, с источником. **Bedrock ~2.5·10¹⁰ кг/м³ — не реальная плотность**, а подгонка под гравитацию. Нужно подтвердить. |
| 6. Мультилоадер (NeoForge) | Очень большой объём | Отдельный модуль, отдельные миксины, JarJar Sable Companion. Sable Companion API не проверен. |
| 7. Рендер без задержек, Sodium | Очень большой объём | Миксины в рендер, интерполяция, совместимость с Sodium 0.6.13/0.8.x. Нужны тесты на клиенте. |
| 8. Мягкие тела (XPBD) | Большой объём | Ядро солвера, тетраэдры, объём, ESPEFs. Лимиты 1000/5000 частиц — мерить. |
| 9. Желе, пружины | Средний объём | Зависит от 8. |
| 10. Пружинные тела | Средний объём | Есть пружины в `mechanics.rs`. |
| 11. HD-модели в Blender | Вне возможностей агента | Blender-GUI недоступен. Агент может сгенерировать `.obj` процедурно, но не художественно HD. Нужно решение пользователя. |

Все «sable»-привязки (Sable Companion, `projectOutOfSubLevel`, `getContaining`, `isInPlotGrid`) остаются непроверенными, как и раньше.

## 3. Непроверенные утверждения из ТЗ

- BoneHitboxLib, «Solid Mobs», crouch-stick: названия и поведение не проверены в этой сессии.
- BoralancesShaders, Realis: не проверены.
- «Sable: HD-текстура воды, не стекло»: не проверено.
- ESPEFs и XPBD: XPBD — известная техника (Macklin et al., 2016). Конкретные параметры ESPEFs не проверены.
- Плотность Bedrock: см. таблицу выше.

## 4. Порядок работ (предложение)

1. Этап 1: игрок на теле. Исправить толкание, добавить «ехать с телом». Проверка: харнесс (частично) + живой клиент пользователя.
2. Этап 2: точные меши по VoxelShape для блоков с нестандартной формой (ступени, плиты, заборы).
3. Этап 3: снять жёсткий лимит тел и добавить прикрепление блоков к телу. Замеры при 1000 блоков.
4. Этап 4: плотности в датапаке и таблица из ТЗ с источниками.
5. Этап 5: 3D-вода (SPH) как отдельный модуль с LOD. Замеры dam break, hydrostatic.
6. Этап 6: модульная структура `common/fabric/neoforge`. Перенос кода без изменения поведения.
7. Этап 7: рендер. Миксины в клиентский рендер, Sodium, интерполяция.
8. Этап 8–9: XPBD, мягкие тела, желе, пружинные тела.
9. Этап 10: модели для ассемблера и пушки. Зависит от решения по Blender.

Каждый этап: код, тесты, замеры, лог в `validation/alpha.6-<этап>.txt`. Этап не отмечается «сделано», пока не проверен в игре пользователем.

## 5. Решения пользователя (получены)

1. Охват: все 10 этапов в одном релизе alpha.6.
2. NeoForge: сейчас, вместе с Fabric (common/ + fabric/ + neoforge/).
3. Вода: SPH полностью заменяет 2.5D-воду.
4. HD-модели: процедурно кодом или скачать Blockbench CLI (агент не использует Blockbench GUI).
